JSPI + OPFS probe

Binary file access from synchronous Rust in this page. The check writes a test file, reloads this page to verify persistence, then deletes it.

The next check suspends inside SQLite's file-open callback and reads an OPFS marker before running SQL. The database itself stays in memory.

Read-only database check: copy a known fixture into OPFS, query its pages through SQLite's suspending read callback, then remove the copy.

Storage-only write check: offset writes, truncation, visibility before and after close, and abort. This does not write through SQLite.

Writable SQLite check: buffer pending bytes, publish at sync, then reopen the OPFS database. One connection and a memory rollback journal; no crash-safety guarantee.

Reload check: commit an OPFS database, reload this page, and verify the stored bytes and SQL rows in a fresh WASM instance before deleting the test database.

Exclusive access check: opens a second tab to attempt the same database while this tab owns it, then retries after release. Keep both tabs open until completion.

Owner termination check: opens a committed database in a helper tab, queues for its lock, then closes the helper and verifies the database in this tab.
